# Changelog

## 2.0.1 — 2026-11-20

- The 2.0.0 release did not reach NuGet; this version carries the same changes. Test sources follow `dotnet format`.

## 2.0.0 — 2026-11-20

- **Breaking — order details required.** Every payment endpoint requires `buyer` (name, surname, identityNumber, email, gsmNumber, city, country, zipCode, ip), `billingAddress` (contactName, address, city, country, zipCode) and at least one `basketItems` entry (id, name, category1, itemType, price); a `PHYSICAL` item also requires `shippingAddress` (payment providers do not start a payment without them). `CreateIntentAsync`, `CreateMarketplaceIntentAsync`, `DirectMethodPaymentAsync` (typed and raw), `SplitPaymentRequest`, `MarketplaceClient.CreateCheckoutIntentAsync` and the marketplace card charges throw `LunixiConfigurationException` naming the missing paths (`buyer.email`, `basketItems.0.category1`, `shippingAddress` …) before sending; on the checkout intents `buyer.ip` may be left out (the Lunixi form takes it from the browser). Card storage (`StoreCardAsync`, `POST /payments/cards`) requires the buyer and billing address: `StoreCardRequest` gains `Buyer` and `BillingAddress`.
- New constants: `OrderDetails.RequiredFields`, `OrderDetails.BuyerRequiredFields`, `OrderDetails.CheckoutIntentBuyerOptionalFields`, `OrderDetails.AddressRequiredFields`, `OrderDetails.BasketItemRequiredFields`, `OrderFieldErrorCodes` (`payment.order.field_required`, `payment.order.field_invalid`), `OrderFieldReasons`; `OrderDetails.MissingFields(body, basket, checkoutIntent)` lists the missing paths.
- Split payment requests take `buyer`, `billingAddress`, `shippingAddress` and `basketItems`; `SplitPaymentFields.Payment` includes them.
- Wallet card top-up (`Wallet.Topups.StartCardAsync`) requires `buyer` and `billingAddress` (`shippingAddress` optional) and checks them before sending; a missing field is HTTP 400 `payment.order.field_required` with `details.fields`.
- **Breaking — subscription customers.** `Subscriptions.Customers.UpsertAsync` requires `name`, `surname`, `email`, `gsmNumber`, `identityNumber` and the billing address (`billingAddress`, `billingCity`, `billingCountry`, `billingZipCode`), and accepts `billingContactName`, `shippingContactName`, `shippingAddress`, `shippingCity`, `shippingCountry`, `shippingZipCode`; `phone`, `locale` and `metadata` are not gateway fields and are removed. New constant `SubscriptionCustomerErrorCodes`.
- **Breaking — payment link buyer fields.** `BuyerFieldRequirements` has only `Required` (and `All`); `Hidden` and `Optional` are removed (the gateway answers them with HTTP 400).
- The ASP.NET Core sample stores the order details with the order (`order_details` table) and sends them with the intent.

- `LunixiClient.Reference` (`ReferenceClient`): `ListProvincesAsync`, `ListDistrictsAsync`, `ListNeighborhoodsAsync` for the Türkiye address dictionary used by `ADDRESS` fields.

- `ConfirmActionAsync` now requires at least one of `otp`, `consentAccepted` or `fields`, accepts only a 1–16 digit `otp` and rejects `providerCode` inside `fields`. `ListMethodsAsync` requires a code that starts with a letter. Method field names are limited to 64 characters and a method block may carry 32 fields besides `providerCode`.

- Payment analytics: `FailoverRecoveryAnalyticsAsync` and `ProviderCredentialAnalyticsAsync`.
- Fraud: `FraudClient.RecordEventBatchAsync` (signed JSON array, 1–500 events, `FraudClient.EventBatchLimit`) and `LatestDecisionForPaymentAsync`, which returns the newest decision log of a payment or null.
- `LunixiClient.PaymentLinks` (`PaymentLinksClient`): `CreateAsync`, `ListAsync`, `GetAsync`, `UpdateAsync`, `PauseAsync`, `ResumeAsync`, `DeactivateAsync`, `ActionAsync`, `SendAsync`, `QrAsync` (image bytes as `LunixiBinaryResponse`), `ListAttemptsAsync`, `ListPaymentsAsync`, and link images with `CreateImageUploadAsync`, `ConfirmImageUploadAsync` and `UploadImageAsync`. ## 1.2.0 — 2026-11-12

- `BasketItem.ProductCategory` (`string?`, sent as `productCategory`): optional Lunixi product category code, used by payment methods with legal installment limits (e.g. shopping loan) and other platform features. Null is omitted, so existing requests are unchanged; the API rejects unknown codes with HTTP 400. Codes are exposed as `ProductCategories` constants and `ProductCategories.All`; the property stays a string because the dictionary only grows by appending.

## 1.1.0 — 2026-11-04

- `CreateIntentRequest.EnabledInstallments` (`IReadOnlyList<int>?`, sent as `enabledInstallments`): the installment counts the hosted form may offer for one payment (`[1]` = single payment only). It only narrows the panel settings, the card and the platform maximum; null means no restriction. `CreateIntentAsync` throws `LunixiConfigurationException` before any request for an empty list, a count outside 1–36, a duplicate or a list without 1; the list is serialized in ascending order without changing the request.

## 1.0.1 — 2026-11-01

- Apply the release formatting corrections required by CI; preserve the money-string API and update 1.0.1 installation guidance.

## 1.0.0 — 2026-11-01

- Reject explicit null capture/refund amounts; full remaining operations use omission or the dedicated API described in MIGRATION-1.0.md.

- Breaking: public money request/response fields require canonical minor-unit strings; JSON numbers are rejected.
- Exact signed 64-bit fiat arithmetic and currency-aware decimal text conversion preserve values above JavaScript’s safe-integer limit.
- See [MIGRATION-1.0.md](MIGRATION-1.0.md) before upgrading.


## 0.1.1 - 2026-10-31

- Provide a concrete merchant-site renderer/example using the existing official Lunixi checkout form by default, with an explicit optional hosted presentation.
- Use only the validated backend paymentPageUrl for redirects; its opaque token is independent of the embedded token. Missing URL keeps embedded available and requires reconciliation for hosted mode without inventing another key.
- Preserve authentication, customer ownership/CSRF integration boundaries, no-store/token-redaction rules and raw response compatibility. Existing published tags are unchanged.

## 0.1.0 — 2026-10-31

- Initial .NET 8 SDK with Ed25519 PKCS#8 signing, gateway-compatible compact JSON, token caching and origin-constrained HTTP transport.
- Validated hosted intents, payment status/list/capture/refund/void/methods, split DTOs/actions and fraud clients.
- Raw-body v2 webhook verification, rotated signatures, timestamp and envelope binding, durable replay-store interface.
- ASP.NET Core example with actual paymentId/token response binding, configured merchant validation, authenticated status reconciliation, complete capture/refund balance checks, SQLite attempt persistence and atomic webhook-inbox/order commits.
- Offline cryptographic, transport, validation and host integration tests; NuGet packaging and CI.

This source version does not claim NuGet.org availability or activation of gateway features whose deployment is pending.
